# ESPHOME Argoclima IR

This project lets you use an ESP32 device with IR to interact with the Argoclima Ulisse 13 A/C unit with a WREM-3 remote. Tested with M5Stack AtomS3 Lite.

It exposes a Climate controller through the [ESPHome native API](https://esphome.io/components/api.html), and allows you to integrate the unit in Home Assistant.


## Quick Start

1. Pick your install method:

| Method | How | Best for |
|--------|-----|----------|
| **ESPHome Device Builder** | Create a project, then add the board package | HA + ESPHome add-on users |
| **CLI** | `make compile && make upload` | Users with Python + [uv](https://docs.astral.sh/uv/) |

## Boards

Pick the config for your hardware:

| Board | Device Builder package | CLI |
|-------|------------------------|-----|
| **M5Stack NanoC6** | `argoclima-ir-m5stack-nanoc6.dashboard.yml` | `BOARD=m5stack-nanoc6` |
| **M5Stack NanoC6 + IR unit** | `argoclima-ir-m5stack-nanoc6-ir.dashboard.yml` | `BOARD=m5stack-nanoc6 WITH_IR=true` |
| **M5Stack AtomS3** | `argoclima-ir-m5stack-atoms3.dashboard.yml` | `BOARD=m5stack-atoms3` |
| **M5Stack AtomS3 + IR unit** | `argoclima-ir-m5stack-atoms3-ir.dashboard.yml` | `BOARD=m5stack-atoms3 WITH_IR=true` |

The `-ir` variants are for boards with the M5Stack IR unit (U002) attached and add IR receiver support.

## Installation

### ESPHome Device Builder (recommended)

If you run the [ESPHome add-on](https://esphome.io/guides/getting_started_hassio.html) in Home Assistant:

1. For a new, unflashed board, select **Create configuration** → **Create new project** and complete the name and Wi-Fi setup. For a board already running this project's firmware, use **Adopt** instead.
2. Open the device's YAML editor. Keep the generated `esphome`, `api`, and `wifi` sections, but remove the generated `esp32:` section. The board package below supplies the correct target and framework settings.
3. Add these entries to the `secrets.yaml` used by your ESPHome configuration:

```yaml
ota_password: "a-unique-high-entropy-password"
ha_room_temperature_sensor: "sensor.your_ha_sensor_temperature"
```

The room temperature sensor is a Home Assistant entity used to read the room temperature for the iFeel feature.

4. Add the OTA password to the top-level `substitutions` section:
```yaml
substitutions:
  # Set this to main, a branch, a release tag, or a commit SHA.
  argoclima_ir_ref: main
  ota_password: !secret ota_password
```

5. Add the board package under the top-level `packages` section. It provides the matching `esp32:` target, the climate setup, and the required current ESPHome OTA configuration (`ota: - platform: esphome`). Do not add separate `esp32:`, `external_components:`, or `ota:` sections. For a M5Stack NanoC6:

```yaml
packages:
  yoziru.esphome-argoclima-ir:
    url: https://github.com/yoziru/esphome-argoclima-ir.git
    ref: ${argoclima_ir_ref}
    files: [argoclima-ir-m5stack-nanoc6.dashboard.yml]
```

6. Save and **Install**. Future firmware updates are applied from this same device card with **Update**.

Use `argoclima-ir-m5stack-atoms3.dashboard.yml` for an AtomS3, or the `-ir` variants when the M5Stack IR unit (U002) is attached.

**Wrong board?** If the upload reaches 100% but ends with `Finishing update failed`, the board file doesn't match your chip. Switch `files:` to the `.dashboard.yml` for your hardware and install again.

Set `argoclima_ir_ref` once to test a branch, tag, or commit SHA. It selects the YAML package. Local CLI builds need no override because they use the local checkout.

For example, an adopted NanoC6 with the YAML generated by current ESPHome Device Builder should look like this. Preserve the generated name, friendly name, API key, and Wi-Fi secrets from your device.

```yaml
substitutions:
  name: argoclima-ir-5b1980
  friendly_name: Argoclima IR 5b1980
  argoclima_ir_ref: main
  ota_password: !secret ota_password

packages:
  yoziru.esphome-argoclima-ir:
    url: https://github.com/yoziru/esphome-argoclima-ir.git
    ref: ${argoclima_ir_ref}
    files: [argoclima-ir-m5stack-nanoc6.dashboard.yml]

esphome:
  name: ${name}
  name_add_mac_suffix: false
  friendly_name: ${friendly_name}

api:
  encryption:
    key: !secret api_encryption_key

wifi:
  ssid: !secret wifi_ssid
  password: !secret wifi_password
```

#### Different board

No pre-made file for your board? Point `files:` at `packages/dashboard.yml` and supply the chip settings yourself: `board`/`variant`/`flash_size` matching the physical chip, the `esp32:` framework block from the closest `boards/*.yml`, and your own IR pins. With a receiver, also add `packages/remote_receiver.yml` and the `receiver_id` override (see the `-ir` tops):

```yaml
substitutions:
  argoclima_ir_ref: main
  board: esp32-s3-devkitc-1
  variant: esp32s3
  flash_size: 8MB
  ir_transmitter_pin: GPIO4
  ir_receiver_pin: GPIO5
  ir_receiver_is_inverted: "true"
  ha_room_temperature_sensor: !secret ha_room_temperature_sensor

packages:
  yoziru.esphome-argoclima-ir:
    url: https://github.com/yoziru/esphome-argoclima-ir.git
    ref: ${argoclima_ir_ref}
    files: [packages/dashboard.yml, packages/remote_receiver.yml]

esp32:
  framework:
    sdkconfig_options:
      CONFIG_OPENTHREAD_ENABLED: n
      # copy the rest from the closest boards/*.yml

climate:
  - id: !extend ac
    receiver_id: ir_receiver
```

Omit the receiver file, `ir_receiver_pin`, and `receiver_id` when you have no receiver.

### CLI

1. Copy `secrets.yaml.example` to `secrets.yaml` and fill in your Wi-Fi credentials plus the Home Assistant room temperature sensor for the iFeel feature (`ha_room_temperature_sensor`).
2. Build with [ESPHome](https://esphome.io/guides/getting_started_command_line.html) (add `WITH_IR=true` with the IR unit attached):

    ```sh
    make compile BOARD=m5stack-atoms3
    ```

3. Flash over USB, then watch the logs (`HOST_SUFFIX` is the last part of the device name, e.g. `-5b2ac7`):

    ```sh
    make upload BOARD=m5stack-atoms3
    make logs BOARD=m5stack-atoms3 HOST_SUFFIX=-5b2ac7
    ```

4. Later updates go over Wi-Fi with the same host suffix:
    ```sh
    make upload BOARD=m5stack-atoms3 HOST_SUFFIX=-5b2ac7
    ```
